## Що перевіряється
ТЗ: «стани завантаження/помилки/порожніх даних». Додаткове правило, без якого стан помилки не має сенсу: **збій не повинен втрачати дані користувача і не повинен створювати того, чого користувач не підтвердив.**

| ID | Сценарій | Два види збою |
|---|---|---|
| TC-UI-18 | Каталог: стан завантаження, стан помилки без безкінечного завантаження, відновлення на наступній дії | обрив мережі, 500 |
| TC-UI-19 | Оформлення: помилка показана, кошик і введені дані збережені, замовлення не створено, повторне натискання створює рівно одне | обрив мережі, 500 |
| TC-UI-20 | Розрахунок кошика падає: суми не показуються, оформлення заблоковане, після відновлення все повертається | 500 |
| TC-UI-21 | Обране не показується збереженим, якщо збереження не вдалося | обрив мережі |
| TC-UI-22 | Порожні стани: пошук без результатів, немає замовлень, немає обраного | — |

Запуск лише цього блоку:
```bash
npx cypress run --spec cypress/e2e/ui/network-errors.cy.js
```

## Результат
8 тестів: **8 passed**. Два прогони поспіль без повторів дали той самий результат. **Нових дефектів не знайдено**: сайт коректно обробляє обидва види збоїв.

## Технічні рішення
- **Обрив мережі — офлайн-режим браузера через DevTools Protocol** (`Network.emulateNetworkConditions`), як вимкнений Wi-Fi. Варіант `cy.intercept({ forceNetworkError: true })` не підходить: Chromium непомітно повторює запит, з'єднання якого обірвалось, і повторний запит проходить. У результаті застосунок узагалі не бачить збою. Це виявилось на першому прогоні: тести падали, хоча сайт поводився правильно, тому підхід замінено.
- **Помилка сервера — `cy.intercept` з відповіддю 500 і `times: 1`.** Падає лише наступний запит, тож той самий тест перевіряє й відновлення.
- **Сервер не зачіпається.** Збої імітуються лише в браузері. API-перевірки (`cy.request`) працюють у Node і в офлайн-режимі, тому тест може переконатися, що замовлення справді не створено.
- **Страховка:** `afterEach(() => cy.goOnline())`. Тест, що впав в офлайні, не залишить без мережі наступні тести.
- Офлайн-режим працює в браузерах на основі Chromium (Electron за замовчуванням, Chrome, Edge).

## Що не покрито
- Повільна мережа на всіх екранах. Стан завантаження перевірено на каталозі; замовлення й відгуки показують той самий текстовий стан.
- Збій під час «Почати заново» та завантаження відгуку: той самий механізм обробки помилок, менший ризик.
- Тайм-аути без відповіді (запит висить). У застосунку немає власного тайм-ауту, тож очікуваний результат у ТЗ не визначено.

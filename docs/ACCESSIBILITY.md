## Що перевіряється
ТЗ у вимогах до інтерфейсу прямо називає «клавіатурну навігацію» і «підписи полів». Еталон — WCAG 2.1, рівень AA.

| ID | Перевірка | Як |
|---|---|---|
| TC-UI-13 | Немає порушень рівня critical / serious на каталозі, у картці товару, кошику з формою, діалозі «Почати заново» | axe-core, теги `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` |
| TC-UI-14 | Підписи всіх полів фільтрів і оформлення; доступні назви кнопок-іконок (♡ − + ×); `aria-pressed` у «Обране»; `role="alert"` / `aria-live` для помилок і повідомлень | Точкові перевірки DOM |
| TC-UI-15 | Покупка лише з клавіатури: Enter на кнопках, порядок Tab у формі, оформлення через Enter | Справжні натискання клавіш |
| TC-UI-16 | Діалоги: фокус усередині, Esc закриває, фокус повертається на кнопку, що відкрила діалог | Справжні натискання клавіш |

Запуск лише цього блоку:
```bash
npx cypress run --spec cypress/e2e/ui/accessibility.cy.js
```

## Результат
10 тестів: **9 passed, 1 failed**. Три прогони без повторів дали той самий результат, тож нестабільних тестів немає.

### BUG-7 — Видимий текст кнопок пагінації не входить у їхню доступну назву
| Поле | Значення |
|---|---|
| Серйозність | Low (axe: serious; WCAG 2.5.3 «Label in Name», рівень A) |
| Кроки | Відкрити каталог → перевірити кнопки пагінації (`#prev`, `#next`) |
| Очікувано | Доступна назва містить видимий текст: «Назад» / «Далі» |
| Фактично | `aria-label="Попередня сторінка"` / `"Наступна сторінка"` замінює видимий текст «← Назад» / «Далі →». Користувач голосового керування скаже «натисни Далі», і кнопка не знайдеться |
| Автотест | TC-UI-13 «catalog page» |
| Доказ | [скриншот](evidence/BUG-7-pagination-label-in-name.png) |

## Технічні рішення
- **axe-core без cypress-axe.** `cypress-axe` офіційно не підтримує Cypress 16 (peer-залежність до 15). Тому браузерний бандл `axe-core` читається з `node_modules` і додається на сторінку звичайним `<script>`. Підключення через webpack ламає його UMD-обгортку.
- **cypress-real-events замість `cy.press()`.** Вбудований `cy.press()` у Cypress 16 надсилає події клавіатури, але браузер не виконує дію за замовчуванням: Enter не натискає кнопку, Esc не закриває `<dialog>`. `realPress` натискає клавіші через Chrome DevTools Protocol, як справжня клавіатура.
- **Блокуючі лише critical / serious.** Порушення нижчих рівнів виводяться в лог команд, але тест не валять: так перевірка показує суттєві проблеми й не тоне в дрібницях.
- **Підпис поля** рахується через `element.labels`. Це охоплює і `<label for>`, і `<label>`, що обгортає поле. Наприклад, у пошуку підпис візуально прихований (`sr-only`), і це валідна доступна розмітка.

## Що не автоматизується
- Як звучить сторінка в екранному читачі (VoiceOver, NVDA) і чи зрозумілий порядок озвучення — лише вручну.
- Чи достатньо помітний індикатор фокуса на кожному елементі — візуальна оцінка.
- Масштабування до 200% і робота без CSS.
- Контраст axe перевіряє лише для поточної (системної) теми; другу тему окремо не прогнано.
